# 验证范围

公开源码版基于已经完成本机测试的 0.2 原型。

- 规则、状态、签名、迁移、冷静期取消及资源识别逻辑有自动检查。
- 本机曾使用 Windows 简体中文 OCR、独立模拟窗口与真实角色活动祈愿页验证过。
- 进程启停、游戏退出后的清理、永久解除后停止等待及拒绝后续自启动，曾通过独立模拟游戏进程测试。
- 已回归最小化 / 恢复，以及申请 / 撤销冷静期。真实游戏测试未进行抽卡或消耗资源。

个人截图、状态、凭证、密钥、带有本机路径的测试报告未提交到仓库。

## CI 检查什么

GitHub Actions 在 Windows 上构建 .NET 客户端，并运行 `--self-test --skip-ocr`。
0.3.0 还构建保护组件，并使用独立临时计划与模拟进程检查失效处理、无关进程隔离、冷静期、保存失败回滚及永久解除。测试构建入口不会进入正式客户端。
0.3.1 额外构建服务恢复检查程序，但 CI 不执行这项管理员测试，也不注册 Windows 服务。普通保护集成检查增加故障后再次启动模拟游戏的场景。
窗口兼容组件的隔离检查覆盖双方身份验证、拒绝未授权客户端、拒绝无效窗口，以及完成计划后退出。此项不替代高权限真实游戏的焦点与快捷键测试。
另用临时生成的密钥运行 Python 核验工具检查，验证签名、阈值、不匹配请求和证据时效。
报告明确标记 OCR 被跳过；CI 不安装语言组件、不启动真实游戏、不更改登录启动项。

在装有简体中文 OCR 的本机，去掉 `--skip-ocr` 可增加真实 Windows OCR 引擎检查。
测试返回非零退出码或报告 `passed: false` 视为失败。重复运行应使用新的测试数据目录。

本机窗口回归另外覆盖加载阶段不反复遮挡、正常画面恢复、入口响应、短暂窗口交接、持续故障、切换与最小化。模拟窗口的耗时不能替代真实原神的体验；独占全屏不受支持。
切换与最小化检查还会持续观察普通游玩和祈愿两种场景，确认其他窗口保持前台、游戏被实际收起并维持最小化、切回后继续识别；加载阶段切出不自动最小化。检查同时读取原生窗口状态，不能只以遮挡是否隐藏判断游戏已经收起。这是隔离窗口检查；真实游戏的 Alt+Tab、任务栏及返回桌面体验需要另行确认。
跨进程后台回归使用独立模拟游戏、被动遮挡和真实输入组件，两轮检查普通画面与祈愿画面的切出、持续最小化及恢复保护。另将模拟游戏的界面线程暂停 500 毫秒，连续观察至少 150 毫秒，确认实际收起前遮挡保持，恢复后没有祈愿尝试。该测试不发送实际键鼠输入，不操作真实原神；只在测试构建中提供 `--background-probe <新测试目录> --enforcer <组件路径>`。运行时不要点击其他窗口，否则固定前台窗口断言会被打断，不能记为通过。
此次本机隔离窗口检查为 26 项通过，跨进程检查为 43 项通过。真实原神更新后，使用者反馈切出后游戏仍存在，祈愿遮挡期间无法切出其他应用或最小化，并选择保留该版本。因此真实游戏的自动最小化尚不能记为通过，祈愿期间限制切出是已报告的兼容表现。
另有交互返回回归：确认遮挡不抢走模拟游戏的前台位置、确认键被拦截、Esc 返回、右上角单击返回以及正常游玩恢复。该测试使用实际键盘/鼠标输入或 Computer Use，只运行隔离模拟窗口，不消耗游戏资源。
本机无边框实测已确认铺满屏幕、Esc 与单击返回正常。首次祈愿加载曾出现短暂漏挡；修复首次显示位置及过渡处理后，使用者重新启动真实游戏，确认首次进入不再漏出页面，Esc 与单击返回均正常。这是单机实测结果。
首次显示的位置回归检查覆盖真实窗口创建，确认遮挡立即与游戏客户区对齐；另外使用带阳性对照的独立模拟窗口核对鼠标输入。输入兼容性检查仍有未通过项，不能把正常返回和窗口对齐的检查结果当作强制拦截已完全验证。
资源显示回归检查首次显示、多分辨率、重定位及重新显示后的窗口区域：原有顶部资源与返回区域保持可见，顶部留白下方恢复遮挡，底部祈愿区域完整遮挡。超过本机窗口尺寸上限的合成分辨率只检查区域几何。提供截图时，还检查缩放至 1920 像素后的资源读数；本机另用真实采集路径复现并验证过整栏遗漏零余额的修复。私人截图与本机报告均不公开，此检查不替代所有资源数量与游戏布局的实测。

## 本机计划任务与启停检查

`tests/LifecycleProbe` 使用独立密钥、状态目录和模拟游戏进程，创建并清理一份临时的当前用户计划任务。它检查 Windows 实际启动任务、连续两轮游戏启停、初始化时游戏已退出、永久解除与任务清理。此检查会暂时注册计划任务，只在本机明确运行，不纳入默认 CI。

先构建客户端并在全新的目录运行 `--self-test`，再运行：

```powershell
dotnet run --project tests/LifecycleProbe -c Release -- artifacts/app artifacts/test-data artifacts/fresh-lifecycle-probe
```

第二个路径必须是本轮 `--self-test --data` 使用的目录，第三个路径必须尚不存在。测试不使用实际游戏，也不替用户重启或注销 Windows；登录触发仍需在下一次自然登录时确认。

## 0.3.1 服务恢复检查

`tests/ServiceRecoveryProbe` 必须在可交互桌面中由本机管理员明确运行。它复制测试构建至新目录，使用临时密钥、模拟游戏、无触发器的临时组件任务和一次初始服务启动；测试结束仅清理本轮核对过身份的服务、任务和进程。不得使用真实计划、私钥或正式安装任务代替这些临时材料。

```powershell
dotnet build src/WishGuard.csproj -c Release -p:WishGuardTestHooks=true -t:Rebuild -o artifacts/test-client
dotnet build enforcer/WishGuard.Enforcer.csproj -c Release -p:WishGuardTestHooks=false -t:Rebuild -o artifacts/enforcer
dotnet build tests/ServiceRecoveryProbe/ServiceRecoveryProbe.csproj -c Release -o artifacts/service-recovery-probe
# 在管理员终端中运行；第三个目录必须尚不存在。
./artifacts/service-recovery-probe/ServiceRecoveryProbe.exe artifacts/test-client artifacts/enforcer artifacts/fresh-service-recovery
```

检查覆盖四次服务异常退出、等待组件单独异常、输入组件单独异常、全部组件同时异常、拒绝不匹配的任务定义，以及恢复后重新启动模拟游戏。永久凭证使用本轮临时密钥签发，检查保存完成状态、主动移除服务与任务，及超过恢复延迟后仍不重新启动。检查通过实际进程身份、进程代次、管道身份、任务定义和模拟游戏存活判断结果。

这里的等待组件使用可信心跳探针，输入连接按正式客户端的重连方式重试；它不运行 OCR，不发送实际键鼠输入，也不证明真实游戏的完整会话兼容性。正式安装的游戏画面与操作仍需单独实测。报告与临时密钥均不提交仓库。

本机 0.3.1 普通保护集成检查 24 项、管理员服务恢复检查 65 项全部通过；临时服务和任务清理无错误。此前 26 项窗口检查与 43 项跨进程后台检查是上一轮结果，本轮没有修改遮挡逻辑，也没有重新执行这两组测试。正式更新后，使用者另行确认真实原神正常运行、F3 进入时遮挡及 Esc 返回正常；该实测没有抽卡。

## 不能据此保证的情况

尚未全面验证所有卡池、确认弹窗、持续快速输入、多显示器、HDR/DPI、所有分辨率、独占全屏及未来游戏更新。
没有实测整整 24 小时，时间边界由确定性时间测试覆盖；没有为测试而绕过真实资源阈值。
CI 通过不等于拦截绝对可靠或得到游戏官方认可。
